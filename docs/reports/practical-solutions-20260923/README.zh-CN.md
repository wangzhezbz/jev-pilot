# JevPilot 可行改造方案与原版运行时验证

日期：2026-09-23。结论：有可实施的方案，优先修复证据进入模型的路径，再优化判断本身。当前研究没有证明整体省时或额度节省。

后续实施见[同调用链接入报告](../same-cell-integration-20260923/README.zh-CN.md)。本页与 JSON 保留修复前研究快照；修复后的 `--code-mode-output` 命令验收无效钩子直通，不再以复现旧误报为通过条件。

## 1. 本轮新发现：内部钩子的成功不等于模型收到精简内容

使用本机 `codex-cli 0.155.0-alpha.9.2`、隔离配置、合成模型端点和合成 Jev 回答。命令实际执行、MCP 实际通信，筛选与召回使用本项目真实代码。没有收费 GPT/Jev 调用，也没有改动已安装插件、桌面进程、网络或生产配置。

同一个含目标证据和 350 行噪声的命令输出：

| 路径 | 实际观察 | 判定 |
|---|---|---|
| 直接 `exec_command` → PostToolUse | 下一次模型请求含精简证据 | 原有直接工具路径可用 |
| `functions.exec` 内调用 `exec_command` → PostToolUse | 内部 Bash 钩子生成精简结果，记录 `applied`，但模型仍收到 350 行噪声 | 已复现缺陷，不能算过滤成功 |
| 同一 `functions.exec` 内执行 → `filter_output` → 只输出筛选结果 | 模型收到目标证据与 29 行同块上下文；原文逐字召回成功 | 替代路径原型成立 |

内部钩子没有公开父级 code-mode 标识，仅有 Bash 名称、命令和工具调用 ID。因此仅通过 `tool_name` 排除 `functions.exec` 无法拦住这个场景。也不能看到 `exec-` 前缀就声称所有未来版本都有同一契约。

影响范围须分开：直接工具过滤仍通过；既有 `automatic_output_filter` 日志只能说明本地提交过替换，不能单独证明 code-mode 模型输入已改变。此前 clean-workflow 对照中自动过滤为 0 次，因此本次新发现不能解释那组全部时间/token 增量，也不能推翻其已记录的额外模型轮数和缓存差异。旧数据继续保留。

原型验证了脚本仍拿到完整结果与正确退出码，筛选发生在模型展示之前，不会把供 JavaScript 计算或解析的原始结果改掉。

| 指标 | 嵌套旧路径 | 同调用链原型 |
|---|---:|---:|
| 模型请求数 | 2 | 2 |
| 模型可见工具输出，序列化 UTF-8 字节 | 25,452 | 3,428 |
| 两次模型请求 input 字段合计 UTF-8 字节 | 164,582 | 150,213 |
| 筛选判断批次（合成） | 1 | 1 |
| 原文完整召回 | 原有存档 | 验证通过 |

工具输出减少 **86.53%**；连同工具说明、调用代码和其他上下文计算，本例两次请求 input 合计仅减少 **8.73%**。原型增加的 MCP 工具说明也计入后者。两项均是字节测量，**不是 token、缓存账单、账户额度或整体耗时**。SSE 返回的 token 数为固定占位值，不用于收益报告。

原型关闭了旧自动输出钩子，避免两套筛选重复调用；判档桥仍运行。这是隔离实验，尚不是生产修复。正式接入必须完成重复调用抑制、权限、失败回退和自动使用覆盖率验收。测试的 MCP 工具是仅处理合成文本的只读 fixture，其权限声明不能套到支持配置修改/执行的生产通用工具上。

证据：[汇总](summary.json)、[直接路径](direct_hook_control.json)、[旧嵌套路径](nested_hook_gap.json)、[同调用链](same_call_chain.json)。旧路径测试显示 PASS 仅表示缺陷成功复现，不表示功能合格。

## 2. GitHub 实现中值得吸收的部分

| 项目 | 值得采用的实现 | 在 JevPilot 中的落点与限制 |

| [jev-lens](https://github.com/dizk/jev-lens) | 代码生成候选视图，Jev 选视图，代码提供原文片段并支持 recall | 为日志、搜索结果提供 full/signals/sections 等视图；full 始终可选，未知和矛盾证据保留。其已有集成面向 Pi/Claude，不是现成的 Codex 桌面适配 |

| [jev-codex-router](https://github.com/0xNatoshi/jev-codex-router) | 显式携带缓存命中、缓存时效和上下文规模，保留原始缓存 key | 用于观察和收益诊断。其代理可更换模型；本项目保留用户所选模型，不照搬跨模型策略 |

## 3. 具体实施顺序

### P0：先让真正的输入减少，并杜绝无收益重复调用

1. 对大文件/搜索，直接使用插件内的读取与筛选入口，原文不先返回 GPT。现有 `filter_output(path)` / `search` 可复用；由插件 skill 自动选用，用户不创建文件、不执行命令。
2. 对需要执行命令或调用浏览器工具的场景，在同一 code-mode 调用中串接原生工具与筛选，只把最终需要的内容发给模型。保留原生工具权限、退出码和结构。上面的原型验证了这一条通信路径。
3. 增加独立的只读证据工具边界，避免把生产通用 MCP 工具全部声明为只读。它只接受已有文本/允许范围的文件，不能执行命令或改变设置。
4. 钩子事件分为“生成候选”“提交替换”“宿主确认/未确认”。无法核对模型输入时，不记录“确认节省”。按受测运行时能力识别不支持替换的路径，避免旧钩子与新链路对同一份输出调用两次 Jev。
5. 自动使用覆盖率单独测：自然提问中多少次出现合适机会、实际使用多少次、跳过原因是什么。合成脚本指定调用链不等于已证明 agent 会自动选择它。

这些工作在插件和适配层内部完成，用户仍使用普通桌面对话。Skill 可以引导自动使用，但仅靠提示词不能保证每次命中；达不到覆盖率要求就不能称为透明全自动。

### P1：减少 Jev 自身的输入和等待

- 已知格式先做本地精简；需要语义判断时，让 Jev 在有限候选视图间选择，而不是把整份日志逐块重新阅读。先从日志/测试结果做起，代码编辑和逐字引用保留原文。
- Jev 没看到的内容不能被标成“确认无关”；视图只能算有召回入口的局部证据。来源行号、hash、失败和未完成状态继续保留。
- 缓存按任务目标、内容 hash、策略版本和来源语义隔离；复用已经做过的判断，不跨新任务盲目沿用。不要再次引入刚修掉的跨轮抑制。
- 当前每次请求启动 curl，不能复用跨进程连接。可验证常驻 HTTP 连接池，但必须先通过现有代理、超时、取消、连接失效和密钥隔离测试；保留旧 transport 回退。此项没有新实测，不能预报能省几秒。

### P2：判档优化与真正的整体收益验收

- 保留自动判档、真实切档、人工上限、失败恢复。让判断围绕下一步是定位、实现、测试还是总结，避免因为任务整体复杂就所有步骤高档，或因为某个命令失败就一律升档。
- 优先补原生下一代模型生成边界的能力探测；不存在可靠接口时继续如实报告工具边界，不假装已经实现 Ares 的逐生成租期。
- 比较原生、固定档位、仅过滤、仅调档、组合五种条件；先少量代表场景找收益来源，再做同任务多次、顺序平衡的配对测量。
- 用相同质量验收检查实际修改、失败恢复、必要证据、退出状态；统计总时长、模型轮数、input/cached/uncached/output/reasoning、Jev token/调用/等待、实际切档和实际精简次数。reasoning 已包含在 output，cached 已包含在 input，不重复相加。
- 只有在质量达标并覆盖额外说明、Jev 成本、补读和重试后仍有净收益，才启用该场景的省量宣传。无法测账户扣费时，继续不把 token 推算成订阅额度。

不以删除原有功能、压低质量标准或隐藏负结果来制造收益。收益不稳定的场景可以保留功能，但不能作为已验证的省时场景。

## 4. 本轮交付与复现

新增同调用链合成 MCP fixture，扩展原版引擎验证入口。生产功能、已安装插件、Chrome/VPN 与推理档位均未修改。本轮解决的是可行性验证和缺陷定位，P0～P2 尚未全部实施。

开发者复现命令（不是用户使用步骤）：

```sh
node scripts/verify-desktop.mjs --filter-output
node scripts/verify-desktop.mjs --code-mode-output
node scripts/verify-desktop.mjs --code-mode-chain
npm run check
```

三项协议断言通过；check 检查 341 文件、84 模块通过。只验证当前 macOS 原版运行时，尚未验证 Windows/Linux 桌面。合成链路不衡量真实 Jev 判断准确率或真实 GPT 行为。下一轮应先落实 P0，再决定是否值得运行新的付费整体对照。

# 减少委托准备与取证往返：新旧入口完整任务对照

2026-09-25。本轮直接修复上一轮暴露的接入开销，比较旧回调入口与新可复用入口，而不是重复比较不同业务场景的局部循环。

**Chrome 的同任务完整对照观察到快 28.90%；Computer Use 首次因宿主未激活恢复而更慢，保留原始结果。宿主就绪后的单独复测观察到快 18.08%。全部 5 次最终验收通过。样本小且非盲，不能称为稳定提速或实际账单节省。**

## 已落实的改动

1. **可复用导航入口。** 页面/应用、授权范围和真实任务身份绑定一次；普通任务只传业务目标、阶段和验收条件。任务、会话与原始结果保存在导航对象里，接管后调用 `resume()`，不再依赖跨工具单元重新拼接可变变量。原有复杂回调和单步 API 保留。
2. **完整预算预检。** 委托前只读当前共享预算，检查剩余调用次数、输入容量是否耗尽、等待额度和熔断状态。等待预测使用近期同模型浏览器调用的 75 分位延迟乘 1.5，末次请求保留最低时间；无样本时保守估计。不重置预算、不更换 taskId、不提高额度。预检仅为预测，实际每次请求仍经过原子预算预留；网络变慢或其他调用竞争仍可能导致中途交接。
3. **取证与回执一起返回。** 自动循环结束后另做一次官方宿主的新鲜页面读取，把它随回执返回。Codex 必须读取这些真实文字后判断是否完成；文字足够时不必再花一轮 GPT 仅请求同样的读取。读取失败、页面变化或证据不足仍需原生复查。长页面回执明确标记截断，原文保留。
4. **单步任务直接原生处理。** 预估只有一次动作时不启动 Jev 委托；低置信度、动作限制、新鲜度复查和一次性票据继续生效。
5. **补上宿主激活说明。** Computer Use 新任务开始前先读取当前应用状态；旧 JS 变量存在不代表应用仍处于可操作状态。此次首次 CUA 对照犯了这个准备错误，恢复时间没有从结果中扣除。

Chrome 新入口相对旧入口：耗时少 **28.90%**、GPT 总 token 少 **24.35%**、非缓存输入少 **53.22%**、输出少 **33.10%**。

CUA 宿主就绪后的补充观察相对旧入口：耗时少 **18.08%**、GPT 总 token 少 **23.14%**、非缓存输入少 **14.02%**、输出少 **68.53%**。首次含恢复的 CUA 新入口则慢 **72.95%**，GPT 总 token 多 **22.36%**。宿主生命周期仍是实际使用中的可靠性问题，不能用补充观察掩盖。

这些是新入口相对旧入口的差异，不是相对“卸载 JevPilot”的效果。GPT 轮次从 4 到 3 是流程结构减少；具体秒数还受生成和网络波动影响，不能全部归因于某一行代码。

## 实际预算预检

五次流程的浏览器委托共调用 Jev **30 次**，输入 **25,485**、输出 **1,410** token；另有当前任务后台判档 1 次，合计可归属本次任务的 Jev **31 次、29,636 输入 / 1,516 输出 token**。随后用当前真实任务和原有额度验证下一段六步委托的入场检查：普通等待余额约 **2,552.52ms**，近期延迟预测需要 **5,815ms**，返回 `HOST_INSUFFICIENT_TASK_BUDGET`，**0 次页面观察、0 次动作、0 次收费请求**。原生流程仍可继续。

自适应预检也避免固定“每步 1s”的过早拒绝：补充 CUA 流程入场时以 20 个近期样本估计单步 436.5ms，整段要求 3,182.5ms；六步随后确实完成。预测不是完成保证，硬限额未更改。

## 测量边界

- 对照顺序固定为 Chrome 旧→新、CUA 新→旧。遇到宿主未激活后保留首次 CUA 结果，增加一次公开标记的就绪复测。没有盲测，每个条件仅一次，且测试者已熟悉任务。
- 计时包含页面导航、每次任务定义/会话创建、Jev 循环、独立最终宿主读取、Codex 核对并形成答案，以及发生的恢复。不含共用测试框架、插件安装、文档阅读和报告生成；启动工具调用在计时前生成，但它的 token 纳入用量。
- 两边使用同一官方宿主；Computer Use 实际操作 Safari。Chrome 与 CUA 结果分开。
- 旧入口按照上一版已验证流程调用，单独取一次最终页面；新入口把相同性质的新鲜读取合并到回执。两边都有最终观察和 Codex 复核，没有用删除验收换成绩。
- 全部 Jev 响应模型为 `jev-1.13.0`。原生模型、用量、缓存以及后台档位信息见原始审计。时间窗内 20 条原生代次记录均为 high；一次后台判档也保持 high。没有因新入口切换 GPT 模型来制造节省。同窗内其他任务或无法归属的三次调档调用单列审计，不计入当前任务成本。
- 总 token 包含大量缓存输入，不能乘普通输入单价。正常 Chrome 配对和 CUA 就绪观察中，GPT 缓存/非缓存输入与输出均下降，Jev 仅各多 30 个输入 token、调用次数及输出不变；实际金额仍取决于账户计费，未读取逐任务账单。
- 30 次实测包含第一版固定等待预检和补充流程的自适应预检；最后交付自适应版本。旧结果没有被新版本追溯替换。

# 连接复用修复与缓存归因纠正

2026-09-24，接续 [上一轮完整任务报告](../investigation-20260924/README.zh-CN.md)。这次实际修改了请求实现，并重新验证了之前未通过的真实证据筛选。没有用新结果覆盖旧失败，没有改 VPN、账户、主模型或现有推理档位策略。

## 已落地的解决办法

### 1. 复用连接，取消每次启动 curl / 重建 TLS

原来每次判断都启动独立 curl，无法在不同判断之间复用连接；证据请求即使总截止设为 5 秒，连接阶段仍有单独 2 秒截止。

现在在进程内使用 HTTPS keep-alive agent，复用同一代理配置下的连接。证据请求受原有任务预算和本次总截止控制；独立路由接口仍受原有 2 秒总截止控制。超时、取消和断流不自动重发付费 POST，避免同一个判断发生重复消耗。代理变化选择新的 agent，空闲旧 agent 会关闭；不修改全局代理或全局 agent。

使用 Node 原生连接池和代理支持：[Node.js HTTP 文档](https://nodejs.org/docs/latest-v24.x/api/http.html#built-in-proxy-support)。低于 Node 24.5、SOCKS 代理或显式 curl CA 配置保留原 curl 路径；这属于发送前兼容性选择，不是失败后重复请求。密钥只出现在请求头，不写 argv、文件或诊断记录。

### 2. 相关证据保留修复完成真实验收

上一轮已修改“成功判断后不要把明确相关证据推迟”，但在线验收遇到 TLS 超时。本轮以同一来源哈希、同一任务和预算，通过生产 transport 再测一次：**通过**。

- 实际 Jev 调用：1 次，jev-1.13.0，约 **750 ms**。
- 调查加原文恢复校验总计：约 **767 ms**。
- 必要的正式规则、修正文档、归档草案三份来源全部保留；missingRequired=[]、deferred=[]。
- 保留 7 个窗口、排除 5 个；没有因预算要求二次补读；原始快照恢复完全一致。
- 输入 11,498 / 输出 437 token。筛选结果含 4 个额外保留窗口，是保守保留，不声称完美筛选。

接口判断及 usage 结构按 [TypeSafe API 文档](https://docs.typesafe.ai/api) 校验。

### 3. 把“缓存坏了”的推测纠正为逐步归因

没有重写正常缓存。重算上一轮所有单次生成回执后，发现两组首步缓存条件不同：

| 两次任务合计 | 原生组 | 候选组 | 候选减原生 |
|---|---:|---:|---:|
| 首步输入 | 30,374 | 32,088 | +1,714 |
| 首步缓存命中 | 8,832 | 0 | −8,832 |
| 首步未缓存输入 | 21,542 | 32,088 | +10,546 |
| 后续各步未缓存输入 | 18,027 | 15,606 | **−2,421** |
| 全任务未缓存输入 | 39,569 | 47,694 | +8,125 |

首步差异大于总差异。后续未缓存输入实际上少 **13.43%**。这反驳了“仅凭总量就认定会话内缓存被插件破坏”的判断；仍不能证明跨任务缓存为什么出现首步不对称，也不能从观察值中直接扣掉 8,832 后宣传省额度。原始 +20.53% 总结果保留。

新增 cache-breakdown 脚本，使后续报告必须把首步、后续、缓存输入、未缓存输入分别公开。新增 transport_timing 事件，记录连接是否复用、套接字分配、请求写完、首字节、总时长和错误类型，避免继续把全部等待笼统称为模型耗时。

## 真实连接测试

预先固定顺序 curl → pool → pool → curl → pool → pool。相同的小型颜色判断、相同模型和请求内容，禁止自动重试，全部保留。六次均正确，输入均 293 / 输出均 31。

| 顺序 | 方式 | 是否复用 | 毫秒 |
|---|---|---|---:|
| 1 | curl | 否 | 623.59 |
| 2 | 连接池 | 否 | 496.78 |
| 3 | 连接池 | 是 | 279.64 |
| 4 | curl | 否 | 571.17 |
| 5 | 连接池 | 是 | 278.76 |
| 6 | 连接池 | 是 | 259.38 |

旧方式两次平均 **597.38 ms**；连接复用后三次平均 **272.60 ms**，本次观察低 **54.37%**。两次 curl 的 TLS 阶段分别约 336 / 271 ms；连接池复用回执证明后三次未重新建立连接。新方式第一次仍需连接，单列为 496.78 ms。

这是 6 次组件请求的小样本，不是整个 Codex 任务提速 54%，也不证明所有代理和网络已稳定。单次 token 不变；这项修复直接减少网络调用开销，不伪装成 token 优化。

本轮共 7 次实际 Jev 调用：6 次小判断加 1 次真实筛选，全部成功；已知输入 **13,256** / 输出 **623**，未知用量 0。没有再次启动付费 GPT 整体 A/B；上一轮的完整任务结果依然有效且未达发布门槛。

# 整体复查：优先降低总耗时和总成本

日期：2026-09-25。基线 `c1dd4c11700483c9cef001863e7921a6190b5593`。目标是用户保持普通 Codex 工作方式、质量不下降、减少整项任务等待和总成本。总 token 不是唯一目标；缓存输入、GPT 输出和 Jev 输入不能按同一价格相加。

## 结论

目前最需要改善的不是增加第十五个功能，而是减少重复判档、提高现有委托入口的实际覆盖，以及建立完整任务的成本验收。十四项有代码不等于十四项都在普通对话里无条件自动生效，也不等于十四项分别证明了经济收益。

本轮修复三项可复现问题，保留主模型、证据保护、概率门槛、任务预算和人工档位优先。没有靠强制降档、扩大额度、跳过验收或隐藏失败获得结果。

## 本轮修复

### 1. 维持原档位时，例行预算过早耗尽

旧版连续维持原档位时最多间隔两个工具边界，四次例行判档可能在前半段用完。短流程重复付费，后面的简单步骤在没有明确阶段消息时反而没有例行判断可用。

v18 在同一阶段连续三次有效确认维持用户原档位后，最多间隔五个工具边界复查；仍受原有 60 秒租期限制。新输入、失败、显式阶段变化立即打破复用，并重置连续计数。自动降低后的档位不适用这个延长规则，过期且没有预算时仍恢复用户原档位。无效结果不累计连续次数。

代价：没有显式阶段信号的简单步骤可能晚几个工具边界才被识别。这期间保持用户原档位，不降低推理质量；不保证每个工作负载都受益。

### 2. 完整过滤没有预查共享预算

旧版只检查本次操作 `maxCalls`，没有检查真实任务剩余 calls/bytes/wait。已知整批无法完成时仍可能先付一笔请求，随后降级并返回全部原文，付费没有换来输出减少。

现在基于未缓存批次，在第一次请求前检查共享预算的确定性不足；原文保持不变、预算不重置、缓存命中不占新请求。预检只是只读快照，不是抢占或完成保证；实际请求仍原子预留，网络变慢和其他操作竞争仍可能触发安全回退。只有必须完整判断的路径使用该拒绝逻辑，允许部分筛选的普通接口不受影响。

### 3. 答案校验失败丢失已有用量

旧版先校验答案，再记录用量。服务端已经返回 usage 但答案格式错误时，token 被记录为未知。现在先保留经过整数/非负检查的用量，再校验答案；失败仍算失败、不缓存、不应用排除。负数、字符串和缺失值继续标为未知，不按零成本处理。

## 修复前后机制对照

以下是冻结旧源码与新源码、相同模拟判断的离线对照，**不是付费模型性能数据**。没有把模拟等待换算成实际加速百分比。

| 场景 | 旧版 | 新版 | 正确性边界 |
|---|---|---|---|
| 同阶段六个工具边界 | 4 次判档 | 3 次判档 | 两边均保持 high |
| 后段才出现简单步骤 | 4 次，后段无剩余例行判断 | 同为 4 次，最后一次识别并应用 low | 原生发布由模拟回执验证；协议另验 |
| 整批调用余额不足 | 1 次请求后仍返原文 | 0 次请求，直接返原文 | 原文逐字相同 |
| 整批输入预算不足 | 1 次请求后仍返原文 | 0 次请求，直接返原文 | 原文逐字相同 |

两项预算修复消除的是可确定没有收益的请求；第一项只在部分稳定流程少问一次，长流程不一定减少总请求。不能外推整体省时、省钱比例。

初版对照脚本的模拟响应漏填 confidence，路由器正确拒绝它，两组均保持 high；该无效夹具结果保留在 [首次记录](mechanism-initial-invalid-fixture.json)。补齐协议字段后的 [有效对照](mechanism-comparison.json) 与 [脚本](../../../scripts/acceptance/overall-audit.mjs) 一并提供，不覆盖失败记录。专门验收没有额外付费 Jev/GPT 请求；开发对话及自动后台判档消耗不计入该离线对照。

## 十四项逐项结论

| 功能 | 现状与不足 | 下一步重点 |
|---|---|---|
| 自动判断 | 批量/缓存/回退可用；普通语义工作仍由 Codex 选择调用 | 以是否替代 GPT 工作作为准入依据，避免额外问一遍 |
| 推理强度 | 有真实回执；稳定阶段重复保持占多数 | 本轮 v18 缩减重复检查，后续配对实测质量与净耗时 |
| 搜索筛选 | literal investigate、原文恢复有效；不是全库语义扫描 | 固定初始查询和候选范围后做未见样本测试 |
| 输出过滤 | 直接钩子可用；嵌套工具结果不能靠钩子替换 | 普通任务同调用内 prepare/输出，避免原文先进入 GPT |
| 工具选择 | 必用项零调用已生效；不改写宿主工具注册表 | 检查可选工具筛选是否实际少了模型选择负担 |
| 失败恢复 | 有界建议、熔断、取消均保留；13 个超时记录说明网络仍有成本 | 分离连接/服务等待；避免过短截止制造重复工作 |
| 质量验收 | 必测与不确定项保留；不能替代最终验收 | 测发现缺陷和避免返工，不能只统计判定速度 |
| Chrome/CUA | 新 navigator 有小样本收益；宿主就绪/激活仍有不稳定性 | 冷启动、恢复和失败成本纳入任务计时；本轮未重跑 UI |
| 项目记忆 | 需授权，来源与过期核查有效 | 用跨任务真实重用验证价值，不为了覆盖率自动写记忆 |
| 用量统计 | 本轮补齐失败答案已有用量；面板仍非整任务成本结算 | 汇合 GPT 非缓存/缓存/输出与全部 Jev 调用，价格缺失明确未知 |
| 上下文交接 | 可恢复交接与缓存存在；不改写原生历史 | 不宣称回收已消费 token；当前压缩样例未达目标，需要独立校准 |
| 审查/测试选择 | 必测免问、可选项保守筛查；小样本有节省 | 检查漏掉重要测试的风险与返工总成本 |
| 检查点 | 自动记录与来源核验存在；没有盲目重放 | 跨中断恢复验收，而非只验证写入成功 |
| 原文提取 | 返回原文偏移并校验；不保证实体理解正确 | 用歧义、无答案、相似实体做功能和成本配对 |

## 尚未解决的交付问题

1. **收益验收仍不充分**：Chrome/CUA 的新旧入口小样本有改善；工程任务自动调档没有稳定胜过固定 high 的证据，二者不能合并宣传。下一次应冻结版本，交替顺序，保留超时和返工，按等质量完整任务比较总成本与时间。
2. **接入范围不能夸大**：技能/MCP 不会截获每个工具。嵌套结果需要 agent 在同工具调用内使用 prepare；上下文交接不是原生历史压缩。已修正文档入口中的笼统描述。
3. **版本升级仍是维护成本**：精确兼容门槛保护未知 Codex 协议，但新版本会原生回退。需要维护验证与升级交付，不能用宽泛版本通配符掩盖协议风险。
4. **成本视图仍不完整**：六模型支持不等于六模型定价齐全；当前估价表缺少 GPT-5.6 Terra/Luna 时返回未知。API 等价估价不等于 ChatGPT 套餐扣额。
5. **跨平台成品仍有边界**：CI 不等于 Windows/Linux 桌面实机验证；依赖打包、签名和面向普通用户的安装体验仍需独立完成。

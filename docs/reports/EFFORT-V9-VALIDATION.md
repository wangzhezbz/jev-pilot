# Fewer repeated judgments and safer task continuation

2026-09-23 · Policy `effort-v9-context-batches`.

## Implemented

- **Reuse across an observed tool batch.** The verified native runtime publishes a usage update after a response's tools and hooks. Tools with observed native IDs in the same usage epoch share one existing lease decrement, including staggered starts. A group is capped at 16 tools and the existing 60-second TTL. Missing tool IDs fall back to ordinary boundary accounting; malformed/decreasing usage disables grouping for that turn. Failure, changed progress, user input, manual controls and stale evidence retain their fences. This is bounded accounting over observed events, not a new native model-generation API.
- **Narrow routine-progress handling.** Exact short acknowledgments such as “检查通过，继续原计划” remain evidence but do not invalidate reuse. Unknown wording, conflicts and changed plans still trigger reassessment. There is no general semantic suppression of progress.
- **Automatic historical context on continuation.** A short continuation request can restore the same project's and thread's checkpoint after restart. It must be at most 24 hours old. Routing gets a bounded historical task, progress and pending work with source turn, timestamp and mandatory-review metadata; the latest request takes precedence. Recorded eligible file hashes are rechecked. Changed files remove stale progress/pending entries; incomplete snapshot coverage stays explicit. The start path waits at most 150 ms for recovery and otherwise continues without it. Normal full task requests do not inherit this context automatically.
- **Checkpoint provenance and asynchronous snapshots.** Irrelevant stream deltas are rejected before project/config/checkpoint access. Git and file-content reads run asynchronously, with 40-file/1 MB-per-file limits and Git timeouts. Completion is forwarded without waiting for that snapshot. Version and turn checks prevent a late snapshot from overwriting a newer turn; orderly shutdown flushes pending writes. Current plans and receipts are separate from inherited records, and repeated continuation retains original-task provenance. Automatic replay remains disabled.
- **Accounting.** Completed-turn logs and runtime summaries separately count reused batch results, routine acknowledgments and restored checkpoint context. These are observed actions, not inferred savings.

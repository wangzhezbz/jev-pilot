# 证据筛选与交接优化

2026-09-24。**本轮改善了筛选组件的等待时间与完整工具输出体积，没有证明整个 Codex 任务的 token 或耗时已经下降。**

## 改动与用途

1. 独立筛选批次从串行改为最多两组并行。问题、阈值、调用预算不变；失败批次仍保留原文，不能拿并发失败冒充排除结果。
2. 普通只读工具的 `context` 自带覆盖与回读说明。此前正文和覆盖信息分离，按工具说明只输出正文会丢掉后者。现在主模型可以知道保留、判断排除、预算延后和去重各有多少条，也被明确告知判断不保证正确。
3. 普通只读工具精简每条记录重复的概率分布，保留判定类型、来源、失败原因、原文身份和保护状态。高级工具与内部 API 保留详细结果。
4. `recall` 新增原文关键词查询和分页。关键词、ID 或来源的字面匹配由本地代码处理，不调用 Jev。可按具体缺口回读，仍可恢复完整原文。零匹配不等于语义上没有相关证据。

这些改动不改变主模型、推理路由策略、筛选阈值或验收要求。没有禁止主模型必要的全文核验。

- 235 项本地回归通过，包括六模型保持、原文身份、保护项、预算不足、网络失败、两批并发失败与精确回读。

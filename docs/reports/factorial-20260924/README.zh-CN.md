# JevPilot 十二次诊断对照报告

日期：2026-09-24（Asia/Shanghai；原始日志使用 UTC）

**12/12 次任务通过独立功能验收，但仍未证明稳定省时或节省账户额度。** 两项开启组相对原生组，三项任务耗时合计减少 **6.36%**，GPT 总 token 减少 **18.90%**，未缓存输入却增加 **67.83%**。实际发生 **2 次原生确认的 high → low 切换**，语义筛选、同单元预处理与原文召回的实际调用均为 **0**。不能把未使用的功能算成性能收益。

这是冻结版本后的诊断实验，每个任务每种配置只运行一次；不是有充分重复次数的性能基准，更不是全部 14 项功能的端到端验收。没有为了得到好看的结果删掉失败、替换样本或重复挑选。

## 4. 为什么总 token 少了，仍不能说省额度

### 4.1 缓存变化不能忽略

两项开启组：未缓存输入从 **57,658** 增到 **96,769**；缓存输入从 **441,856** 降到 **308,224**；输出从 **11,264** 降到 **9,254**。总 token 把不同计费类别相加，会掩盖这个变化。

两个实际切档的任务都出现：切档后的下一次有用量生成，其输入缓存命中为 0。

| 日志任务配置 | 切档前一次输入／缓存 | 切档后一次输入／缓存 |
|---|---:|---:|
| 仅调档 | 26,138 / 25,600 | 26,909 / 0 |
| 两项开启 | 19,671 / 15,616 | 20,659 / 0 |

**这是时间顺序上的关联，不足以证明强度修改必然清空缓存。** 服务端缓存、请求路由和负载没有被控制；本轮也未采集完整模型请求用于逐字比较。但在查清前，不能宣称切档没有缓存代价。

若 GPT 的每个 token 单价分别为 `p_uncached`、`p_cached`、`p_output`，两项开启相对原生的 GPT 费用差是：

```text
39,111 × p_uncached − 133,632 × p_cached − 2,010 × p_output
```

还要再加 Jev 费用。此处没有假定 GPT 单价或 ChatGPT 套餐额度换算规则，也没有读取账户账单，所以**实际省了多少钱／多少套餐额度：未验证**。

### 4.2 较少生成和较短读取路径也会减少总 token

两项开启组有用量增量的生成次数为 19，原生为 23。按照逐次原生用量做恒等式分解：

| 两项开启相对原生的差额来源 | GPT token 差额 |
|---|---:|
| 生成次数减少，对原生首轮输入的重复次数减少 | −58,980 |
| 初始输入差异在各次生成中重复，含插件描述等差异 | +17,647 |
| 后续历史增长差异 | −53,188 |
| 输出差异 | −2,010 |
| 合计 | **−96,531** |

该分解严格相加等于实际差额，是记账恒等式，不是因果分解。没有实际筛选调用，就不能把历史增长差额记成“Jev 压缩节省”。三个任务中，原生和插件组的搜索、读取、测试与汇报路径也不同。

### 4.3 路由预算花在了收益出现之前

跨文件与仓库任务中，Jev 在前期多次选择 high，复查间隔经常为 1；等到后期给出 low，常规预算已到边界。当前保护规则拒绝开启一个可能很快因预算耗尽而回退的降档，产生了 **4 次 `budget_held`**。另有一条 medium 建议因证据已变化被替代。

保护规则有合理的保真目的，但当前预算分配未有效覆盖后期低难度阶段。不能通过直接删除保护或锁定低档来制造节省。相关实现在 [`router.mjs`](../../../runtime/desktop/router.mjs) 的预算检查、复查周期和基线回退逻辑。

### 4.4 Jev 自己也有开销

| 配置 | 请求数 | 成功／失败 | 已知输入 token | 已知输出 token | 请求耗时之和 | 已知输入估算费用 |
|---|---:|---:|---:|---:|---:|---:|
| 仅自动调档 | 13 | 12 / 1 | 21,230 | 1,272 | 12.680s | $0.000891660 |
| 调档＋筛选 | 15 | 15 / 0 | 29,358 | 1,590 | 11.360s | $0.001233036 |

总计 28 次请求，已知输入 **50,588**、输出 **2,862**。按 2026-09-24 查阅的[官方模型价格](https://docs.typesafe.ai/models)，输入每百万 token $0.042，输出免费，已知输入估算 **$0.002124696**。1 次超时没有返回用量，不能按 0 token 或免费处理；该估算不是完整账单。

请求耗时相加约 **24.04 秒**，可能与其他工作重叠；不能直接从整任务时间里扣除，反推出模型推理时间。两项开启组的 GPT 加 Jev 已知 token 算术总和为 **445,195**，比原生少 **12.84%**；跨模型 token 相加只表示记录的数量，不是价格或套餐额度。

## 5. 测试方法与独立验收

- 模型：GPT‑6 Sol；初始 high。原生版本 `codex-cli 0.155.0-alpha.16.3`；插件 `0.2.0+codex.20260923233124`；路由策略 `effort-v15-functional-reevaluation`。
- 原生组：原版 app-server，不装插件；仅调档组：真实路由，无插件及自动筛选；仅筛选组：安装插件并启用自动入口，路由使用不调用 Jev 的固定 keep 对照；两项开启组：真实路由与插件全部开启。筛选组因此也包含桥接和插件开销，不是一次纯筛选函数调用。
- 同一任务四组提示、初始文件和验收器相同。每组新建合成仓库与独立原生配置目录，仅使用已有授权；无其它 MCP 插件。原生默认 code-mode 保留，由模型自然发现、读取 Skill 并选择工具。没有强制全量读日志或强制 Jev。
- 单并发，每个任务每种配置 1 次，顺序预先冻结并交错。三种任务无法使四种顺序位置完全平衡；服务端缓存、网络负载和模型随机性仍可能混杂结果。
- 跨文件修复：tenant/account 复合键、带冒号键碰撞、同键 Promise 同一性、不同租户独立、成功／失败清理、同步异常、普通返回值、无额外未处理拒绝，以及零／负金额和币种保真。测试前验证原始缺陷被拒绝、正确参考实现通过。
- 日志分析：540 行、64,072 字节，8 条远距离证据；识别连接池回归、排除 DNS 假说、12/80=15% 失败率、恢复参数、后续 200 请求无失败、结算影响仍未知，并核对原始证据编号。
- 仓库定位：370 文件、365,293 字节，包含生产配置、调用链、历史作废方案和过期风险；独立检查 driver、请求头、租户隔离、持久化、900 秒窗口、过期后风险、未知事故发生率以及 8 处必要来源，所有既有文件不变。
- 仅调档桥接的 Jev 账本位于默认 Store，按唯一合成项目标识只读导出；其余组使用每次独立 Store。核实相关全局／项目无配置覆盖。避免把仅调档组的空自动化账本误算成零调用；路由回执中的用量不再叠加一次。
- 付费推理共 12 次，不重试、不替换样本。本轮总 GPT 用量 **1,870,994 token**，任务耗时合计 **996.771 秒**，另加 Jev 已知 53,450 token；1 次 Jev 超时用量未知。编写测试、主会话后台路由和撰写报告的消耗不在这十二次配对账内。

## 6. 统计修正与证据边界

原生仓库组收到 9 条用量通知，其中第 5 条重复了第 4 条累计值和 last 用量。若直接累加 last，会多算 **27,858 token**。分析器保留全部原始通知，按累计增量对账，只计 8 次有用量增量的生成；最终累计值仍为 **204,779**。其他 11 组没有此重复。所有分项相加已核对。

缓存输入是输入的子集，reasoning output 是输出的子集，不再重复计入 GPT 总 token。命令 `durationMs` 遥测仍出现 0，不能视作命令无耗时。报告另保留工具生命周期的观察区间，但没有把剩余时间全部归因于 GPT 推理。

这里运行的是与桌面相同原版引擎的 app-server，以及冻结的适配层与插件；不是桌面 UI 点击到显示的延迟。当前桌面加载状态、Chrome 网络和其它模型／Windows／Linux 的真实设备表现，不能由本轮 macOS、单模型数据外推。功能质量通过不等于所有模块已验收，更不等于效率达标。

## 7. 下一步应先处理什么

1. **先核验缓存代价。** 对两个切档后的零缓存点做最小对照，分开“保持 high、固定 low、同任务中切档”；记录请求前缀身份和原生用量，查清是设置变化、路由还是其它缓存因素。保留原始任务质量要求，不能以总 token 下降代替成本下降。
2. **重新分配路由判断预算。** 避免在信息没有实质变化的早期反复判 high，给后续验证／收尾保留可用预算和复查能力。保留新输入、失败、过期证据的重新评估，不能直接关掉保护。
3. **单独验收自然采用预处理的路径。** 使用确实需要语义筛选的真实候选集，并记录外层最终展示的内容。确认一次自然任务中有“准备 → 实际展示 → 必要召回 → 质量通过”的完整链路；没有实际采用就不能宣称整任务压缩生效。容易用精确搜索解决的任务继续跳过收费筛选。
4. **之后才扩样。** 保持同一验收标准，增加顺序平衡的重复次数及其他模型。当前数据适合定位上述问题，不适合发布固定加速率／省额度比例。

本轮仅新增测试与报告，没有修改运行中的路由策略、安装包、VPN 或 Codex 配置，不需要用户再次重启。

# JevPilot 全面实测：时间、GPT token、质量与失败记录

2026-09-25 · macOS 实测 · 原版 Codex 后端 + 官方 Chrome / Computer Use。首次冻结版本 20260925164800，入口修复 20260925173800，最终收窄入口 20260925175000；前两阶段结果不冒充最终版本完整矩阵。

**结果有明确的场景差异，不能宣传为全面加速。** 首次冻结的 Sol 组有总体收益，Astra 组总体变慢且增加 GPT token；Computer Use 文档导航减少了 GPT 往返，Chrome 则暴露了交接与共享预算耗尽后的额外开销。失败、计量异常和修复追加数据全部保留。

最终版本的仓库定位追加对照 4/4 通过，两对均更快：耗时 −36.00%、GPT token −20.97%、含 Jev 的 API 等价费用 −30.35%。这仅对应该场景的两对实测，不是最终版本全矩阵或普遍收益。36 次模型任务和 10 次界面任务最终功能验收均通过，首次界面记录有一次计量异常。

## 本轮修复与未解决的问题

1. **命名大文本入口漏检。** 目标文件排在目录枚举后面、文件名后带句号时，现在可正确识别；只检查元数据，不读取正文或调用 Jev。搜索提示避免通用行号和时间戳。
2. **工作目录歧义。** 两次自然语义任务都曾把 `workspace` 传成 `.`，MCP 在插件目录解析导致 ENOENT。现明确要求任务绝对目录，并在任何处理前验证；错误会指导 agent 使用正确 cwd，不让用户手工补文件。修复后的实际 MCP 调用及状态见追加组。
3. **元数据采样偏差。** 原来只看前 80 个文件，可能全是小代码文件；现在仍最多 stat 80 个，但分散到完整列表。无命名文本时跳过逐路径名称匹配。识别覆盖改善不等于必然加速。追加两对仓库定位都出现负向结果后，最终版本不再对以 find/locate/trace 或查找/定位/追踪开头的任务自动推荐广泛调查；工具仍可使用，命名大文本和广泛 review/reconcile 提示保留。
4. **Astra 的复杂生成仍未解决。** 首次跨文件候选多出约 74 秒，Jev 请求累计仅约 2.25 秒。额外生成轮次、工具定义输入、生成/网络等待共同存在；没有证据把全部差异归因于 Jev 延迟。两次实际降档都较晚，不能据此承诺复杂代码工作受益。
5. **浏览器目标拆分与预算回退。** 多条件整体目标在入口处可能不够明确，交接会增加 GPT 轮次。长会话共享预算耗尽后也可能为一次不执行的委托付出额外轮次。本轮保留这些保护，没有为了好看而关闭验证、修改权限或增加额度。
6. **查询与结果恢复仍有开销。** 宽泛 OR 查询可能匹配大量噪音并提前触及检索上限；外部判断超时后，GPT 需要恢复取证。追加样本中的此类情况单独记录，不能把工具成功返回当成真实 Jev 筛选成功。

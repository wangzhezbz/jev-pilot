# 2026-09-25 全面验证方法

目标：在完成质量不退步的前提下，观察 JevPilot 是否减少任务耗时和 GPT token。费用按公开 API 价格另算，不用总 token 代替费用，也不把估算当作 ChatGPT 套餐实际扣费。

## 冻结与顺序

`protocol.json` 在性能调用前写入。首轮候选版本为 `0.2.0+codex.20260925164800`，底座是原版 Codex `0.155.0-alpha.16.4`。源文件、任务输入及验收脚本的摘要随各组协议保存。先跑 Sol 的四类任务，再跑 Astra 的跨文件修复和日志调查；每类两个重复，按 AB/BA 交替。两组保持同一模型，初始 high；候选允许 Jev 推荐并实际调整 effort，禁止用模型降级冒充同模型收益。

浏览器组另行串行执行。Chrome 用官方扩展，Computer Use 用官方 macOS Sky 控制 Safari；全部操作通过官方 Node REPL。文档和报表各有版本、语言/地区、状态等干扰选项，包含不得执行的修改按钮。每个目标需要六步导航，报表反转选项顺序。基线由当前 GPT 根据每次新鲜 AX 状态选择操作，不是预先编程的点击答案；候选由 GPT 提供业务目标，Jev 在当前候选中选择，GPT 验收最终新鲜状态。

## 质量判定

- 跨文件修复：独立代码断言验证租户和有分隔符键的隔离、并发 Promise 身份、成功和失败清理、同步异常、再次重试、零值/负值/币种保真，以及无多余未处理拒绝。原规范和 smoke 不得修改。
- 日志调查：必须找全冻结的事件证据，准确计算失败率，并保留被否定的假说和未观测范围。原文件不得修改。
- 370 文件仓库：正确追踪 HTTP、记账、去重、提交四个实现路径，区分当前 ADR 与过时草案，识别租户范围、持久化、900 秒窗口及过期风险；没有现场观测就必须回答未知。
- 180 条语义筛选：按固定独立 oracle 验收，区分重复结算、授权冻结、独立购买、已退款及仍待处理的事项。
- 界面：核对记录身份、版本、语言/地区、发布/批准状态及只读预览文字；错误记录、修改陷阱或验收失败文字均不通过。所有 Jev 接管失败和原生恢复都保留。

## 计量边界

模型任务计时从 `turn/start` 到原生 `turn/completed`，包含模型等待、工具与路由等待；进程、插件初始化另列 startup，含启动总时间也提供。它是桌面同一原版后端的隔离任务，不是桌面窗口动画延迟。

界面数据来自当前真实长会话中带标记的操作片段，包含开页/进入目标、动作、两次调用之间的 GPT 处理和最终验收。首次工具单元执行前的模型生成有原生 token 记录，但计时从首单元执行开始；公共插件引导、文档读取、公共测试辅助函数与报告制作不在每个片段内。因此它不是从新会话首次安装开始的完整冷启动费用。两组共用已经连接的官方宿主。

界面组的 `bare` 仅表示 GPT 原生导航：当前桌面的后台判档在两组中都保持启用，后台请求另外核算。这不是卸载 JevPilot 的界面对照，不与隔离模型组的 `bare` 定义混用。没有为测试改动用户其他任务的全局配置。

GPT token 取原生用量记录，区分缓存输入、非缓存输入、输出与推理输出。推理输出已包含在输出中，不再次相加。界面片段逐工具单元匹配原生生成记录；缺失或重复匹配会中止统计，不按字符数估算。长会话历史会重复计入输入，所以还列出 GPT 生成次数和非缓存输入。

Jev 用量取实际调用账本，判档日志只用于核对实际改档，不再加一遍用量。报告区分业务调用与当前会话后台判档。未返回用量的失败不能按零元处理；有未知调用的组合只列已知费用及未知数量，不给精确总费用节省率。

## 功能证据与性能证据

回归测试验证确定性逻辑及异常分支；27 组原版协议测试验证真实引擎调用参数、缓存上下文、手动设置、失效回退，以及 Astra/Sol/Luna 和 5.6 模型兼容。协议测试的模型响应是合成的，不计入付费性能结果。

12 组真实 Jev 功能验收覆盖分类、缓存、检索/恢复、输出筛选、工具选择、恢复建议、质量/翻译检查、完成证据、授权记忆、可恢复上下文交接、改动评审、检查点及原文抽取。这里的“上下文交接”不会重写 Codex 原生历史，“恢复建议”不自动执行危险操作，“工具筛选”不移除原生工具。功能测试通过不等于每项功能均已证明能省 GPT token。

## 不能外推的结论

这些是已用于开发的合成用例，不是未见过的生产工作负载。每个模型/任务仅两个重复；每个界面/目标仅一对。本轮不作统计显著性或普遍节省承诺。Mac 的真实界面测试不能证明 Windows/Linux 实机兼容；六步 AX 点击不能证明图片识别、坐标操作、输入、滚动、登录或任意站点自动化。

首次冻结结果和随后因缺陷修复而进行的追加验证分开报告，追加样本不能替换不利结果。所有结果使用相同完成标准；中途超时、配额及基础设施失败保留，未完成的配对不拼成有利的总体百分比。

# 文档准备与 Computer Use 修复复测 · 2026-09-25

**本轮修复在两个已知反例上得到正向结果：两轮文档对照、两轮 Computer Use 对照全部正确，耗时和含 Jev 的估算费用均下降。** 这是针对已知样本的回归复测，不是新的未知样本验收，也不能证明所有任务都有同等收益。[上一轮负结果](../holdout-20260925/README.zh-CN.md) 保持原样。

候选版本 `0.2.0+codex.20260925205500`。运行时调档策略仍为 v19；修改的是证据表示、收益准入、AX 控件解析与页面范围辅助接口，没有关闭原有语义筛选、召回、判断、切档、权限检查或失败接手能力。

## 修了什么

1. **整段复用与来源开销。** 旧版以重复句子为主，且每个小记录附加一套来源标记。新版同时寻找重复整行和句子，优先替换更长的原样文本，只输出实际使用的字典项；表示使用连续来源区段，保留每条记录、原始位置、空白和异常。返回前逐项核验展开后与原文相同，完整原文仍可召回。
2. **把附加开销计入准入。** 无损表示的收益检查包含返回元数据、调用参数及 2,048 字节的工具说明预留。它是保守的字节准入代理，不是假装测得 GPT token；实测 token 单独取原生用量回执。
3. **按页面子树提取可访问性文本。** 新增 `createWebScope({title,url})`，从官方宿主的新观察中绑定确切页面身份，按缩进取原样子树，排除浏览器工具栏。无需页脚独立成行，也不依赖子节点是 `文本` 还是 `text`。缺失、身份改变、多个 web root 均停止；旧自定义 scope 仍可使用。
4. **兼容 CRLF 控件行。** 仅在解析控件候选时处理行末 CR；原始观察及新鲜度校验保持原样。

160 组包含中文、俄文、不同空白、矛盾记录和标记碰撞的离线还原检查全部通过。上轮 90 条请求材料的完整序列化返回由 **17,653 字节降至 4,641 字节（−73.71%）**；全部 90 个 ID 保留，召回与原文一致，压缩过程没有付费模型请求。这是字节变化，不能直接称为 GPT token 降幅。[离线数据](offline.json)

两轮新版均为 **5 次真实 Jev 判断、5 次实际操作、0 次额外接手**。Safari 最终仍合并正文和页脚，新 scope 正常返回这条完整文本，GPT 独立核对最终结果。10 次调用与持久账本逐笔一致，共 Jev 输入 8,466、输出 530 token，估算费用 $0.000355572。没有重置任务额度或换假任务 ID。

局部执行循环分别为 7.024、6.782 秒，**没有**把它们冒充上述完整操作窗口。窗口包含 GPT 中间决策及最终判读，不包含工具初始化、导航器绑定、首次任务构建或报告整理。所有页面来自只读合成应用。

GPT token 来自 20 个标记调用对应的原生回执：每轮原生 7 次 GPT 生成，新版 3 次。在当前很长的会话中，每次都重传大量已缓存历史，因此总 token 数较大；它不是新增生成文本量。两臂运行在同一已安装 v19 的 Astra high 宿主，比较的是逐步原生 UI 决策与候选 Jev 导航器，不能当作独立短新会话的插件开关收益。两组样本不足以给出稳定性能保证。

## Chrome 的剩余边界

另做了一次功能检查，未混入上述性能样本。Chrome 自动翻译把英语按钮变成中文，事先限定的英文名称失配。导航器两次正常停止，未付费猜测、未执行未授权按钮；GPT 接手后完成了正确的 Maple 准备情况查询。

**因此本轮 Chrome 结果是“原生接手后完成”，不是新版全程自动通过，更不是新的 Chrome 提速数据。** 对自动翻译导致的控件名及完成条件变化，仍需结合当前语言构造目标或继续原生执行；不应直接放开全部按钮、关闭用户翻译设置或重复无效委派。该现象此前已出现，不能据此认定本轮 scope 修复破坏了 Chrome。[完整接手证据](ui/chrome-smoke.json)

# 主模型保持：同入口档位对照

日期：2026-09-24。计划 6 次，实际尝试 4 次、完成验收 3 次。第 4 次达到预设 240 秒截止，按停止规则结束，后两次未运行，没有重跑或删除失败。

**本轮没有证明自动判档优于固定 high；不能据此启用自动换模型，也不能宣称稳定节省。**

## 方法

全部使用 GPT-6 Astra 和同一冻结插件 `0.2.0+codex.20260924124913`。工具、skill、工作区初始文件、提示和质量要求相同。固定 high、固定 medium 两组使用不调用 API 的 keep 控制；自动组从 high 开始使用真实 Jev 判断。证据能力对三组同样可用，实际调用均为零。

使用新编写、此前未运行的跨文件重试客户端缺陷：方法与状态限制、幂等键、原始对象保持、Retry-After、指数退避、输入验证、异常身份和完整交付。隐藏验收含 59 个契约检查，模型只看到规格与待修代码，看不到验收脚本或参考实现。独立检查原规格和 smoke 未修改，并要求诊断文档存在。该单一任务仍然只是合成样本，不代表真实项目总体。

顺序预定为 high→medium→auto、auto→medium→high。第二轮未完成，不能当完整平衡试验；即便全跑完，medium 仍在中间位置，不能声称消除了所有顺序影响。

## 限制和停止原因

- 240 秒截止会请求原生中断，原始状态因此记录为 `interrupted`。时间线在 240002ms 收到中断完成；这次不是用户取消，也不是已确认的服务端故障。原始记录不做回写。
- 截止任务的 token 是收到的最后用量，未报告的在途生成用量不能按零处理，也不能把它当便宜完成。停止点独立验收仍记录所有可见产物。
- 耗时含本任务路由与工具处理；启动时间在 CSV 单列。没有测桌面点击延迟或订阅额度。
- 主模型保持由路由请求结构回归、相同任务模型参数及路由目标记录支持；本次没有捕获全部服务端原始请求。六模型协议回归不等于六模型性能测试。
- 两次自动任务不能与仅一次的固定组相加后计算总体节省率。未运行任务没有 token 或时间数据。
- 本轮与之前裸 Codex / 插件比较分别保存，不拼接、挑选或重复补跑。

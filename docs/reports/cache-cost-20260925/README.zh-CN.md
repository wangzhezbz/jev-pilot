## 针对性修改

- 日志模板把整组完全一致的数字字段固化为字面文本。每条记录、位置、前导零、负数、小数和异常仍保留，返回前逐字验证可逆。原文随时可召回。无额外 Jev 请求。
- 此用例表示体积从 16352 降至 15285 字节（6.53%）；这是离线确定的体积差，不冒充 GPT token 或费用节省率。实际前后性能没有做旧插件与新插件的直接配对，不能把本轮全部收益归因于此小改动。
- 费用分析新增每代缓存命中比例、非缓存输入、费用四项和“此前有缓存、随后为零”标记；记录未知原因，避免自动归咎切档。
- 原生协议测试新增缓存键一致性断言；可观察到工具/指令变化时也拒绝通过。顶层工具及指令哈希在当前协议缺失时保留 null，不冒充验证。
- 基准协议补充日志投影模块哈希，明确冻结被测代码。

## 根因边界

上轮 JevPilot 在 high 不变时出现清零。本轮**不加载插件的原生组也出现缓存清零**，说明该现象可独立于插件发生。候选组本轮没有清零，不能声称已修好服务器缓存。原生对照第二次的缓存清零也放大了本轮费用优势。

原生引擎 + 合成端点验证：4 次请求，high 到 medium 的更新仍保持输入只追加、初始前缀及缓存键一致。它证明该受测适配路径不重写旧前缀，不能证明真实服务命中率。尚无实际服务请求正文/服务端路由证据，无法区分服务路由、缓存生命周期等具体因素；未通过修改原生 Codex、插入人工预热或重试来制造命中。

## 实验边界及后续

运行时 codex-cli 0.155.0-alpha.16.4，经两份协议核对，与上一轮同为 alpha.16.4；运行时版本变化不能解释这两轮差异。采用本轮 AB/BA 原生对照；相同任务、初始 high、单并发、冻结独立验收。费用与速度不完全同向：第一对耗时 -1.37%，第二对 +22.97%。无 Chrome/Computer Use 改动，本轮未重测它们。

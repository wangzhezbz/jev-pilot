# JevPilot v13：并发筛选、取消过期任务、减少无效恢复

日期：2026-09-23。基线提交：`a44a5d4c96a8324a6ddd0c2835ae6a99044747d5`。本轮付费测试仅调用 Jev，没有调用 GPT。

## 结论

相同合成日志、相同请求内容的四组配对测试中，自动筛选由顺序等待改为最多两批并发，平均组件耗时 **1,193 ms → 655.25 ms（观察减少 45.08%）**。两组 Jev 输入、输出 token 完全相同，8 次均保留八条关键事实，并真正替换了交付内容。

这是输出筛选环节的实测改善。不能据此声称整个 Codex 任务快 45%、减少 45% token，或已经证明订阅额度节省。

## 从真实桌面发现的问题

本次重启已真实加载 v12，运行文件指纹匹配。当前普通会话的起步判断为 `keep`，high 没有变化；随后一次判档超时 2,071 ms，延迟恢复请求再次超时 2,069 ms。两次失败没有带来切档，未知用量不能按零计费。

其他普通桌面任务出现了 `baseline_no_benefit` 跳过记录，说明 v12 的重复有效判断限制已生效；但该限制没有覆盖当前会话这种“一次有效维持原档位 + 后续超时重试”的路径。当前会话与其他任务在原始证据里分开记录，不混用回执。

另从代码和复现确认：

- 两批独立筛选请求串行等待，网络耗时相加。
- 新输入到来后，旧筛选仍继续请求；完成后虽然不应用，已经消耗的调用仍存在。
- 迟到的旧轮次工具结果可能按新任务目标再次进入筛选。
- 取消请求被混入服务失败统计；其用量缺失仍须单独保留。

## 本轮修复

1. 自动输出筛选最多两批并发，共用原有任务请求、字节和等待预算。普通显式分类默认仍为串行；没有取消预算或提高概率阈值。
2. 筛选结果按原始候选 ID 恢复顺序，网络返回先后不影响证据顺序。部分失败继续返回原文，不能因半份结果掩盖信息。
3. 新输入取消旧筛选；桌面 `turn/start`、`turn/steer`、`turn/interrupt` 接入取消。改需求后，本轮进一步自动筛选保守暂停，直到新提示到来。
4. 旧轮次工具结果在网络调用前跳过；退出时先取消并收拢请求，再关闭数据库。
5. 取消次数单独统计；缺失用量仍标未知，不声称取消请求免费，也不把它当作服务故障触发熔断。
6. 已有有效判断维持用户原档位后，如果复查失败，本轮不再安排推测性的延迟恢复请求。首次请求失败的有限恢复、已自动降档任务的复查与恢复继续保留。代价是可能错过同轮稍后的降档机会。
7. 输出边界标识加入任务 ID，避免不同任务碰巧复用轮次/工具 ID 时统计冲突。

本地复现当前会话的超时轨迹：调用 **3 → 2**，最终均保持 high。节省的是第二次失败后的额外请求机会；不是宣称能消除首次超时，也不是新做的付费 A/B。

## 付费配对实验

预先固定计划：两种日志排列 × 两次重复 × 串行/并发两组，共八次组件运行、最多十六次 HTTP 请求。四对执行次序为 AB、BA、BA、AB；失败保留，不补跑挑选结果。

两组使用同一版实现，仅切换调度并发数 1/2。每对序列化请求哈希集合完全一致，缓存关闭。故障日志与上一轮保持相同构造，包含跨块边界事实、时间线、反证和无关服务记录。质量门槛是预列八条事实全部保留、自动输出替换真正发生、封装后字节减少至少 20%。这不是对模型最终自然语言结论或代码质量的验收。

| 配对 | 顺序 | 串行耗时 | 并发耗时 | 并发相对变化 | 质量 |
|---:|---|---:|---:|---:|---|
| 0 | 串行 → 并发 | 1,184 ms | 628 ms | −556 ms | 两组通过 |
| 1 | 并发 → 串行 | 1,215 ms | 728 ms | −487 ms | 两组通过 |
| 2 | 并发 → 串行 | 1,213 ms | 642 ms | −571 ms | 两组通过 |
| 3 | 串行 → 并发 | 1,160 ms | 623 ms | −537 ms | 两组通过 |

| 指标 | 串行组 | 并发组 |
|---|---:|---:|
| 组件运行 / 通过 | 4 / 4 | 4 / 4 |
| HTTP 请求 | 8 | 8 |
| 平均组件耗时 | 1,193 ms | 655.25 ms |
| Jev 输入 token | 48,424 | 48,424 |
| Jev 输出 token | 1,752 | 1,752 |
| 失败 / 缺失用量 | 0 / 0 | 0 / 0 |

响应模型均为 `jev-1.13.0`。本轮总计 Jev 输入 **96,848**、输出 **3,504** token。按当日[官方价格](https://docs.typesafe.ai/models)输入每百万 US$0.042、输出免费，估算 **US$0.0040676**，未读取真实账户账单。此次并发优化没有降低 Jev token；主要改善等待。

四对并发均较快，但样本少、仅一种合成日志场景，不代表生产环境分布或总体收益。并发会让同一时刻的请求数增加，最多两批；接近共享预算上限、网络异常时仍可能保守退回原文，不保证每次都有收益。原路由和筛选之间的先后关系没有调整，保护必要恢复的优先顺序。

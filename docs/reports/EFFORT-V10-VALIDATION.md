# 限次恢复、连续续接与筛选收益记录

2026-09-23 · `effort-v10-bounded-recovery`

## 本轮完成

1. **临时网络错误允许限次恢复。** Jev 连接、DNS、服务器或超时错误发生后保持原有保守处理；如果此前自动降档，先尝试恢复用户基线。冷却 15 秒后，只在后续工具边界、任务仍有效且预算允许时补试一次。没有后台轮询，不延长单次请求截止时间，不增加既有总预算。认证错误、无效回答、TLS 错误、预算拒绝和原生设置状态不明确不会触发该恢复。新输入或失败不能绕过冷却；中断和过期结果仍不能发布设置。日志区分恢复已安排、边界获准恢复及后续实际判档回执。
2. **连续续接保留原始任务名称。** 同进程多轮“继续/重启了/开始吧”沿用带来源的原始任务名称，而不是将它逐轮替换为“继续”。内存与持久断点共享续接识别规则，保留来源任务 ID 和待核验标记。内存历史受同工作目录、24 小时时效约束；新任务取代后续续接目标。普通续接即使已有内存历史，也会在原来的 150 ms 上限内优先检查持久断点。这里改的是 Jev 路由上下文，不改 Codex 原生历史。
3. **筛选记录最终结果并减少无收益调用。** 每次已执行的筛选记录应用、收益不足、无可用片段、降级、执行错误或旧轮次结果，以及可得的耗时、完整包装后的保留字节比例和证据 ID。只有减少超过 20% 包装字节且其他保护通过，才替换输出；这仍不是 token 节省率。收益不足或无片段时，同项目、会话、目标、工具来源及策略组合冷却 60 秒，期间完整原文直接放行。不同目标/来源/项目不共享冷却，原有每轮两次和全局预算仍生效。小输出等本来不应筛选的结果不额外读取冷却记录。旧轮次慢结果不会修改新轮次输出或设置其冷却。

## 验证

- **163 项本地回归全部通过。** 新增 12 项覆盖恢复截止、重复失败、不可重试错误、总预算、中断、新输入、基线恢复、过期结果、连续续接及目标/目录/时效切换、筛选冷却/到期/隔离、失败结果、成功包装字节与旧轮次结果。
- **9 个原版 macOS 引擎场景全部通过。** 超时恢复、持久续接、工具批次、GPT-6 Astra/Sol/Luna 预算恢复、GPT-5.6 Sol 手动设置、MCP 文本筛选、无收益筛选冷却。
- 超时场景：第一次模拟 Jev 超时，第一条模型请求保持 `high`；真实等待超过 15 秒的工具完成后，模拟 Jev 恢复，原生 `turn/settings/update` 返回 `applied`，第二条模型请求为 `low`。这是原版引擎对合成响应的验证，不是普通桌面任务的 v10 生效记录。
- 无收益场景：第一条工具结果被判断为收益不足，未替换；紧接着同来源第二条进入 `no_benefit_cooldown`，原文保留。原版引擎完成三条模型请求。既有 MCP 文本筛选场景仍能正常应用替换。
- 专用验证使用合成模型和评估器响应，没有额外付费 GPT/Jev 请求；当前普通对话仍由已加载的 v9 自动调用 Jev，不能将那些调用当作 v10 的实测效果。

[机器可读证据](effort-v10-validation.json) 只保存必要元数据，不包含原始系统提示、工具正文或凭据。

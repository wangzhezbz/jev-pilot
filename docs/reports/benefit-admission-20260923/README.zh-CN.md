# JevPilot v12：减少无效调用与筛选开销

2026-09-23。修复基线：`5422ad87fa27a99d24558f54f355fc6c2d678042`。策略：`effort-v12-benefit-admission`。

本轮修复已经落地，并验证了减少冗余判档、本地排序开销和真实日志筛选效果。**没有测出或声称整任务稳定省时、GPT token 净下降或订阅额度节省。** 之前性能不佳的报告保留，不用这次局部结果替换。

## 改了什么

| 问题 | 处理 | 代价与边界 |
|---|---|---|
| Jev 连续维持原档位，仍因每次公开进展反复判档 | 连续两次有效判断均停在用户原档位，本轮停止后续判档；新用户输入或手动设置重新开放 | 可能错过同一轮后段降档机会；优先减少已观察到的空转。低档位仍复查，必要时恢复原档位 |
| 明确通过的机械检查进展打断长复查间隔 | 识别严格限定的常规进展表达，继续沿用当前间隔 | 失败、新问题或未匹配表达不会当作常规通过 |
| 自动筛选最多两次调用，内容却需要三次以上 | 与实际调用共用批次规划，超过预算或单项超限时零请求返回原文 | 此处按不命中缓存保守预检；不保证后续网络请求成功。仍受任务总预算约束 |
| 长篇质量检查在请求构造后默默退化 | 调用前检查完整 state 和问题，超限明确返回 `not_evaluated / INPUT_TOO_LARGE` | 全文一致性不能靠随意分段冒充；由 Codex 接续 |
| 部分保留时重复分词、反复比较全部已选候选 | 每条候选只分词一次，增量维护最大相似度 | 不更改概率阈值、错误保护或选择规则 |
| skill 鼓励“多一道检查”，却未替代主模型工作 | 调用前确定要替代的阅读或判断；小任务、已知答案直接处理；筛选后按需补读 | 属于行为指导，无法保证每个主模型都严格遵循，仍需普通任务实测 |

用户原档位继续作为自动调档上限；没有为了制造 token 降幅强制降档。

## 真实 Jev 筛选

付费前固定测试计划和质量标准，两个合成日志排列各运行一次，不重试失败观察。每份 360 行，含交叉块边界的故障事实、时间线、反证和大量无关服务日志。通过真实 `createAutomation` 输出适配路径，要求八条指定事实全保留、实际替换输出、封装后字节至少减少 20%。

| 日志 | 原文 UTF-8 字节 | 实际交付字节 | 字节减少 | 路径耗时 | 关键事实 | 自动替换 |
|---|---:|---:|---:|---:|---|---|
| 时间顺序 | 33,338 | 16,945 | 49.17% | 1,368 ms | 8/8 | 是 |
| 块顺序反转 | 33,338 | 16,947 | 49.17% | 1,242 ms | 8/8 | 是 |

每次都判断了 12 个块、排除 6 个块、没有延后块。原文保存在本地，可按需取回。这不是桌面真实 GPT 任务，而是自动输出组件的真实 API 验证；日志设计明确含大量无关内容，不能外推到所有日志。

另做一次短内容质量规则检查，验证新的 `state.content` 输入结构，被判断为通过。

真实调用合计：

- 响应模型：`jev-1.13.0`。
- HTTP 调用 5 次：两份日志各 2 次，质量检查 1 次；失败 0，缓存命中 0，缺失用量 0。
- Jev 输入 24,638 token，输出 915 token；累计请求等待 3,088 ms。
- 按 2026-09-23 获取的[官方 Models 文档](https://docs.typesafe.ai/models)输入每百万 token US$0.042、输出免费，估算本次 Jev 费用 **US$0.0010348**。这是标价估算，未读取账户账单。
- GPT 调用 **0 次**；GPT token、真实额度和任务总时间的净节省 **未测量**。

筛选两份日志本身用了 24,212 输入 token、876 输出 token。Jev 与 GPT 的 token 单价和计费方式不同，不能直接相加后声称省钱；筛选又增加了约 1.2–1.4 秒，只有后续模型减少的等待和成本超过它才有净收益。

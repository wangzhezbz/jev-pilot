# 同一次工具调用内的证据筛选：实施与回归

日期：2026-09-23。插件版本：`0.2.0+codex.20260923231723`。

## 已实施

- 新增只读 `jev_evidence` 工具，只有 prepare / recall 两个入口。继续保留原有 `jev_pilot` 的全部操作。新入口不能执行命令、改变配置或操作浏览器。
- 自动使用指引改为：原生工具取得结果后，在同一 `functions.exec` 中准备精简展示，只输出准备后的 value；脚本仍使用未改变的原始结果。读取已有日志可直接传路径，用户无需额外命令、文件或任务。
- 命令退出码、运行时间等元数据保留。错误、未结束进程、结构化 MCP 数据、图片、注释、JSON、常见分隔表格、代码文件、精确输出和小结果不进入筛选。未知结构保守直通。
- 无密钥、网络异常、取消、未完整判定、没有排除项或减少不足 20% 时，返回原结果。prepare 包装和元数据计入减少比例；与其他操作共用预算，最多两批、并发两批，每批至多 1.8 秒。
- 原始结果作为 artifact 保留；完整召回恢复原来的对象/字符串，不重新执行原命令。部分召回仍可按证据 ID 取原文。
- 当前受测运行时的 code-mode 内部命令使用原生 `exec-UUID` ID；它的 Bash PostToolUse 只透传，不再付费生成无法传到模型的替换内容。原有直接工具过滤保留。识别依赖当前受支持运行时，升级后必须重新验证，不视为永久公开协议。
- 钩子统计改为“提交”和“确认使用”分开；旧记录也归入未确认。新 prepare 只记录已准备视图，不伪造模型回执或 token 节省。五种语言的面板同步显示该区别。
- 判档算法、模型、档位上限、人工设置优先级、Chrome/VPN 配置、原生历史压缩和原命令执行方式没有改动。

## 对正常功能的保护与剩余边界

1. 筛选的对象是给模型看的副本。不能把它当成后续脚本解析的数据；原始对象不修改。代码中的退出码检查和完整噪声行数检查先于筛选，在原版引擎测试通过。
2. 原生执行、权限确认、浏览器图片和结构化状态仍走原生工具。新只读工具没有执行和设置修改入口；它会通过既有 TypeSafe 连接判断所提供的材料，并不访问外部检索结果。
3. 自动使用由插件 skill 指导 agent 选择同调用链。合成测试指定了调用链，**尚未测得所有自然任务的自动采用率**。复杂或未支持的结构继续直通，不为提高覆盖率擅自改变正常结果。
4. 只有 macOS 原版运行时做了本机协议验收；Windows/Linux 的 CI 可检查可移植代码，但不能替代两平台桌面验收。
5. 本轮实现 P0 接入与计量修正。候选阅读视图、本地格式精简、连接池和新的整体配对性能实验属于后续阶段；没有为了省量下调质量标准或修改调档策略。

## 部署

新适配层与插件已更新磁盘安装，保留旧版本和适配层备份。使用独立发布目录供原生插件管理器安装，避免把实验工作目录带入缓存。正在运行的桌面任务没有被终止或强制重启。

**需要一次正常重启才能让当前桌面后台加载新适配层。** 磁盘安装、隔离进程的工具发现与当前任务已加载分别记录，不能互相冒充。重启后的正常使用无需额外命令。

开发者复现：`npm test`、`node scripts/acceptance/native.mjs --out=dist/same-cell-native`；真实付费组件检查需要显式 `node --use-env-proxy scripts/acceptance/same-cell-live.mjs --run`。普通用户不需要执行这些命令。

# JevPilot 优化复核：消除重复证据与无效交接

2026-09-25 · 产品代码 `43202f4d660c4818c7c3d3ce3c3367453710fcc0` · 最终插件 `0.2.0+codex.20260925184500`

**最终 Astra 日志对照中，耗时少 6.81%、GPT 总 token 少 15.90%；API 等价费用仍高 47.67%。不能宣称已全面省钱。** 两个有效配对均更快且 GPT token 更少，一次末轮生成的缓存命中为零显著增加了估算费用。保留中间负向版本和未采用的提示改写试验。

## 本轮实际改动

1. **证据只交给模型一份。** `jev_evidence` 原先同时在 `content` 和 `structuredContent` 返回相同大正文。现在使用单个 JSON 文本块，保留全部字段、证据和原文回读。高级 `jev_pilot` 回执保持兼容。已有解析示例支持两种格式。MCP 没有声明 outputSchema，单份文本结果符合[官方工具结果规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。
2. **重复日志可逐字还原。** 相同 key=value 日志骨架只显示一次，每条原始数值字符串、前导零、顺序、例外、行号和来源均保留；先验证逐字展开一致，再交给模型。保留 exact/code/structured/error 等旁路。该路径不调用 Jev。
3. **减少重复读源。** 大文本提示改为按任务选择初始路径：精确查找用原生搜索，广泛审阅用 prepare；不再暗示先搜索再筛选再通读一遍。
4. **预算拒绝直接给出可用页面。** 零付费、零点击，返回一次通过范围检查的原生页面观察；回执提前说明剩余预计可委托步数，避免下一次无效尝试。取消不读取页面；失败或范围变化不返回未授权状态。
5. **浏览器按业务阶段委托。** 对地区、季度、对象、版本等复合目标，先寻找信息区域，再寻找目标记录，最后检查指定状态；完整 proof 和禁止状态检查保留。没有降低 0.7 门槛、扩大操作授权或提高生产配额。

### 为什么 token 少了，估算费用却增加

最终组原生 GPT 总 token 为 223,773，候选为 188,200；原生非缓存输入为 38,776，候选为 80,928。第 1 对候选的最后一次生成，输入 30,293 token、缓存命中 0；同组其他生成有缓存命中。第 1 对候选首步也没有命中，而两个原生首步各命中 8,832。不能把总 token 当作费用，也不能把零缓存记录删掉或视为免费。

按报告价格快照的 Standard API 等价估算，原生合计 $0.706282，候选含 Jev $1.042989514。8 次后台 Jev 请求合计输入 14,417 token，费用仅约 $0.000606；这一项无法解释 $0.3367 的总差额。缓存状态的差异是账单变化的重要组成，但没有原始服务端缓存诊断，不能断言是插件改变了缓存键。最终组没有实际降档，不能将这些结果归因于调低推理强度。

费用按逐次请求的实际原生用量和价格快照核算；不是订阅额度或实际账户扣款。`cost-summary.json` 还保留 Fast 假设，不能把假设当观察到的服务等级。

### 修改机制的证据

两次真实 prepare 都把 64,614 字节表示为 17,222 字节，零排除、零语义模型调用，原文回读通过。模板中间版两次 prepare 后的下一次 GPT 输入为 40,776 / 40,755 token；单份回执版为 29,212 / 29,121。它们是不同真实任务调用，不能当完全相同模型请求的因果实验，但与回执中第二份正文消失一致。最终两次原生 MCP 完成事件均不再包含重复 structuredContent 正文。

仅减少字节曾经仍增加 GPT token，已在上表保留；最终报告只用原生用量做 token 结论。

以上是官方 Chrome 扩展和 Computer Use 实机的修复验收，使用正常当前任务 ID 和生产共享预算；每个平台一次。阶段目标由 Codex 提供，Jev 逐步选择当前可见控件，禁止写操作，独立读取最终状态。没有把这些循环秒数与上轮完整 GPT 任务时间相除，也没有声称这两次重测证明节省多少 GPT token。它们证明这次六步流程未再发生 Analytics 入口交接。

另有一次 Chrome 预算故障注入：只在测试私有存储设置 taskMaxCalls=1，生产预算未变；在应拒绝的六步任务中确认 0 Jev 请求、0 自动点击，并返回当前页面。随后 Codex 直接使用回执控件执行一步，真实页面到达 Analytics regions。它验证接管链路，不是整任务速度对照。

## 撤回的优化与剩余问题

- 试过仅修改下一步选择提示。计划 16 个配对样本，实际调用 14 次，2 次触及保留配额，没有算作语义通过；报表入口在两个重复中仍然交接。这项产品改动已撤回，原始请求和回答保留在 entry/results.json。
- Astra 复杂跨文件任务尚未重新证明受益；这次有效数据只覆盖日志任务，不覆盖所有场景。
- 缓存未命中原因还未定位，实际费用仍不稳定；不通过强制降智、改模型、忽略未知用量或修改缓存声明制造收益。
- 浏览器仍只委托受限 AX 点击，复杂目标可能交接；提前额度提示是预测，不是预留，其他调用消耗后仍可能拒绝。
- 本轮没有 Windows/Linux 真实宿主操作，CI 成功只证明跨平台构建、回归和打包。

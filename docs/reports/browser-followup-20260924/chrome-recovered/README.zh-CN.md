## 连接恢复

安装版本 `0.2.0+codex.20260924201153` 正常加载后，真实 MCP 工具进程收到代理变量及 `NODE_USE_ENV_PROXY=1`。通过官方 Chrome 插件完成会话命名（0.572 秒）、打开 example.com（0.632 秒）、点击 Learn more 并观察 IANA 页面（1.357 秒）。三段耗时是连接验收，不是任务性能比较。没有再次修改 VPN 或 Chrome 设置，也没有要求再重启。

这支持此前定位的控制通道代理继承问题。旧补丁仅覆盖旧宿主；新版宿主缺少代理配置，且一次性补写会被桌面重建覆盖。启动阶段修复配置后，本次真实控制链路恢复。一次成功不能保证所有网络条件永不复发。

## 方法和原始数据

通过官方 Chrome 扩展实际读取无障碍树并点击本地合成故障处理页面，真实调用 `jev-1.13.0`。每条正确路径六步，含干扰候选和禁止操作。Jev 只接收目标、当前页面和候选，不接收预设正确路径。执行前复查页面、消费一次性票据；结束必须匹配事件编号、记录编号和只读结果。

对照的是旧逐候选分类和新单个 Choice，不是“不用 Jev 的 GPT”与“用了 Jev 的 GPT”。旧代码来自 `d3f4b471f15dd14d4d2480bd4287d5cb74191d1d`，新代码来自 `60fef661b3ddd282e0b6e16d411521bac1549e5c`。单并发、请求缓存关闭、无请求重试。计时包含判断、界面读取、票据复查、点击和最终验收；不含页面重载准备。

## 失败原因与证据边界

1. **真实错误分支**：身份故障要求查看签名密钥轮换。新策略在第 4 步选择部署时间线，第 5 步选择 release r42，而正确路径是认证事件中的 rotation k17。这是路径判断失败，期间没有网络错误或点击超时。
2. **错误路径继续执行**：最终页面显示 `INC-401 event r42`，仍选择会话恢复预览。应用把“只读、可点击”与“符合当前目标”分开处理，但缺少跨步骤目标一致性的及时拦截。当前判断没有收到已走过的语义路径，只收到目标和当前页面；这是代码层观察，不能据此断言加历史就一定修好。
3. **重复点击**：预览出现了新结果文字，页面指纹变化，原来的“相同页面 + 相同动作”防重复规则允许同一预览再点一次。该规则能拦截完全不变的重复，但不能覆盖语义上没有进展的操作。不可简单按按钮名称全局禁用重复，否则会破坏分页等正常功能。
4. **最终验收有效**：要求的 k17 与实际 r42 不匹配，运行没有被记为成功。第 8 次决策返回 review，交回 Codex。没有执行重置、回滚、重启或权限变更。记录见[失败页面](failed-final-observation.txt)。
5. **测试记录缺口**：旧执行闭包没保存中间页面及返回概率，所以无法还原第 4 步精确请求或证明具体是哪些词影响了模型。不能把错误归因于置信度、否定词或候选顺序，除非后续有隔离对照。新探针已记录完整观察、候选和返回概率；这不能补回原样本缺失的数据。

独立恢复：重载同一页面后，按正确路径执行六步，实际获得 k17 结果，耗时 1.051 秒，零 Jev 调用。[恢复记录](manual-recovery.json)单列，**没有覆盖或计入原失败运行**。这是预设路径的界面执行下限，不是 GPT 推理任务速度，更不是 Jev 加速证据。

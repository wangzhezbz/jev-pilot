## 成本统计补齐了什么

原先项目级 Jev 调用没有 taskId，不能可靠合并一个普通 Codex 任务的全部费用。本轮新增调用任务身份和唯一请求 ID，并扩展现有 `metrics` 操作；没有增加一个常驻模型判断或新工具。

- `{taskId, since?, tier?, scope?}` 返回任务级已知用量和 API 等价估价。`scope: project` 默认限制当前工作区；`scope: task` 按真实任务 ID 跨本机工作区汇总。
- 后台判档以原生路由记录作为唯一来源，其余工作流以带任务身份的 Jev 调用为来源；避免同一判档同时计入调用日志和路由回执。缓存命中不作为新的付费请求。
- GPT 按每次原生生成分别计费，区分缓存输入与输出，不把 reasoning 输出重复相加。去重重复生成通知和重复任务结束记录。不同生成的模型独立查价。
- 超时、未知模型、缺失用量、历史无任务身份记录和仍在运行的任务都明确标记。已知小计不是完整账单，也不是 ChatGPT 订阅额度扣除。
- 等待时间单列，多个请求可能重叠，不与 GPT 时间简单相加。统计是用户查询时的本地只读处理，不额外调用 Jev。

[本任务单工作区快照](current-task-cost.json) 与 [跨工作区快照](current-task-cost-all-projects.json) 均来自新源码的本地只读入口，**不是当前旧 MCP 进程已经加载新统计接口的证据**。跨工作区记录正确标出了 1 次未能自动归属的历史格式调用；它没有被当成零费用或强行分给当前任务。这个调用在下面的独立实验窗口中另行验收。

GPT 估价沿用已注明日期的 2026-09-24 价格快照，2026-09-25 复查 [官方价格页](https://developers.openai.com/api/docs/pricing) 中 Astra/Sol/Luna 与 GPT-5.6 Sol 的列值仍一致。未提供 tier 时明确标为假设 standard；未知价格不猜测。缓存写入、其他收费工具、地区附加费及实际账户折扣没有完整账单证据，因此 `accountingComplete` 始终为 false。这些限制使它适合受控对照的已知成本汇总，不适合冒充账户结算。

## 当前插件的真实筛选验证

在当前桌面会话直接使用已经加载的 `jev_evidence prepare`，读取本地合成文本；原文没有先作为工具结果全部输出给主模型，模型只收到处理后的结果。测试者知道样本及答案，单次、非盲测，不是独立泛化验证。

| 指标 | 观察值 |
|---|---:|
| 原始记录 | 12 |
| 必须保留 | 4 条明确相关 + 2 条含糊请求 |
| 实际保留 | 上述 6 条全部保留 |
| 明确无关记录 | 6 条全部排除 |
| 原始字符串序列化字节 | 17,876 |
| 返回 value 序列化字节 | 9,766 |
| 插件完整往返 | 727ms |
| Jev 请求内耗时 | 672ms |
| 实际 Jev 调用 | 1 次、12 个问题 |
| 输入 / 输出 token | 7,862 / 437 |
| 响应模型 | jev-1.13.0 |
| 原文恢复 | 与源文件逐字相同 |

返回 value 的字节数不包含 selection 元数据，不是 GPT token。它证明了普通工具路径能够在输出给主模型前筛选材料，不证明每个工具调用都被自动拦截，也不证明完整任务一定变快。

按 [TypeSafe 官方输入价格](https://docs.typesafe.ai/models) $0.042 / 百万输入 token、输出免费，这次 Jev 请求估价为 **$0.000330204**；没有读取账户实际扣款。开发过程 GPT、后台判档和报告制作不计入这个组件费用，不能将这一个数写成整轮开发费用。

原始文件：[预先确定的样本与验收要求](evidence-plan.json)、[合成源文](fixture.md)、[实际工具返回](evidence-result.json)、[独立验收和实际调用用量](evidence-validation.json)。原文恢复直接核对保存的 artifact，没有额外付费模型请求。没有付费 GPT A/B 任务。
